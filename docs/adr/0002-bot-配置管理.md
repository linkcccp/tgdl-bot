# 0002-bot-配置管理

- **状态**：已采纳
- **日期**：2026-08-17
- **决策者**：architect

## 背景

需求：允许白名单用户在 bot 内修改配置（除 TGDL_BOT_TOKEN / TGDL_API_ID / TGDL_API_HASH 外），但安装时填入的白名单用户/目标频道不可经 bot 修改；修改需持久化并生效（含重启与通知）。现状：`AppConfig` 为 init-only 不可变对象，装配期由 `ConfigLoader.Load` 一次解析；`docker-entrypoint.sh` 仅在 config.conf 不存在时由 TGDL_* 生成；`compose.yaml` 已配 `restart: unless-stopped`。

## 方案对比

| 方案 | 优点 | 缺点 |
| ---- | ---- | ---- |
| A：写回 config.conf | 单一文件、语义统一 | ① 与 .env 形成双写冲突源：用户改 .env 期望重建 config.conf 时因文件已存在而不生效；② 用户挂载只读 config.conf 时写失败；③ 整文件重写丢注释（ConfigParser 不保留注释）；④ 升级/重置场景易丢 |
| B：独立 overlay 文件（StateDir/config-overlay.json + access-overlay.json） | 与安装配置物理隔离、互不覆盖；entrypoint 不触碰新文件；tgdl-data 卷持久（pull 重建不丢）；原子写简单；天然实现"安装配置不可改、bot 配置可改"边界 | 装配期需二次合并（AppHost 一处，成本低） |

生效方式对比：A 热生效（运行期改 AppConfig）vs B 重启生效。热生效需将 AppConfig 改可变或引入运行时覆盖层，且并发数/超时等改动会导致运行状态不一致（DownloadGate、进行中任务）。

命令形态对比：A 命令式（/config list|set|reset、/access add|del|list）vs B 单一向导（按钮流）。向导需回调状态机（多步 + 超时 + 并发），与现有 /cookie 风格不一致，测试成本高。

## 决策

- **存储选 B（overlay）**：`StateDir/config-overlay.json`（键→字符串值，与 config.conf 值格式一致）、`StateDir/access-overlay.json`（`extraAllowedUsers` / `extraTargetChannels`）。新增配置键 `StateDir`（容器内 = `/opt/tgdl-bot/api-data`，entrypoint 生成 config.conf 时显式写入，落在 tgdl-data 卷）。
- **合并机制**：AppHost 装配期 `OverlayApplier.Apply`（显式逐键映射，禁用反射）→ 最终 AppConfig；`EffectiveAllowed = config ∪ overlay` 后传入 `AccessControlService`（其内部不变）。白名单合并仅支持"追加"，config 来源成员不可删除。
- **生效机制选重启生效**：改动 → 持久化 overlay → 写 `pending-notify.json` → 触发优雅退出（`cts.Cancel()`，进程 exit 0）→ entrypoint `wait` 返回 → 容器退出 → `restart: unless-stopped` 拉起 → 新进程加载 overlay 生效。零基础设施改动。
- **重启通知（防重复）**：`pending-notify.json` 记录 {chatId, textKey, args, lang}；新进程就绪后读取 → 先 rename `.sending` 再发送 → 成功后删除；失败保留至下次启动，上限 3 次。
- **可改范围**：AppConfig 除 `BotToken` 外全部键（API_ID/HASH 不在 bot 配置内，天然不可改）；白名单两键不可改（bot 维护独立列表）。路径/连接类键（LocalApiBaseUrl、YtDlpPath 等）允许改但回显风险警告。
- **命令选 A（命令式）**：`/config list|set <Key> <value>|reset <Key>|reset-all`、`/access add|del <user|channel> <id>|list`；仅私聊 + 白名单用户（沿用现有入口检查）。**校验复用 `ConfigParser.ValidateValue(key, value)`**（重构现有校验为可复用方法），禁止 CommandHandler 重复实现规则。
- **权限**：/config、/access 仅白名单用户可执行；通知对象 = 发起者 chatId。

## 后果

- 正面：安装配置（.env/config.conf）与运行配置（overlay）边界清晰；升级/重建容器不丢 bot 改动；命令式无状态、可脚本化、测试简单；重启链路利用既有 unless-stopped，无新基础设施。
- 负面：配置改动需重启（数秒）而非即时生效；overlay 与 .env 并存时存在"两处都能改"的认知负担（list 输出标注来源缓解）；`/config set LocalApiBaseUrl` 改错可致 bot 连不上（删除 overlay 中该键可恢复）。
- 迁移/实现注意：`ConfigParser.Validate` 重构为 public 校验 API 时保持既有错误消息格式；退出前必须**同步写完 pending-notify 再触发取消**；overlay 写操作全部原子（临时文件 + rename）；`access-overlay.json` 与 `config-overlay.json` 分开存储避免互锁。
