# ADR（架构决策记录）约定

本目录记录 tgdl-bot 的架构/数据库/接口/配置契约决策，编号从 `0001` 递增。命名：`NNNN-标题.md`（如 `0001-下载模式.md`）。

## 何时产出

由 `architect` 在每次架构、模块、接口契约、配置键设计决策时产出；开发新功能、新配置键、新接口前优先评估是否需要 ADR。简单改动（纯 bug 修复）无需 ADR。

## 编号规则

- 编号从 `0001` 递增，不重用。
- 决策变更**不修改旧 ADR**：新增一条 ADR，并在旧 ADR 顶部标注「**已撤销**，由 `NNNN-标题` 取代」。
- 用 `git log` 检查当前最大编号。

## 模板

```markdown
# NNNN-标题

- **状态**：已采纳 / 提议 / 已撤销（由 XXXX-标题 取代）
- **日期**：YYYY-MM-DD
- **决策者**：architect / 用户

## 背景

为什么需要这个决策？要解决什么问题？

## 方案对比

| 方案 | 优点 | 缺点 |
| ---- | ---- | ---- |
| A | | |
| B | | |

## 决策

选 A，理由：……

## 后果

- 正面：……
- 负面：……
- 迁移/实现注意：……
```

## 引用

- 日志（`docs/history/`）与设计文档可引用 ADR 编号（如「见 `0001-下载模式.md`」）。
- 代码/配置与 ADR 不一致时，以 ADR 为准，并记录为偏差待修复。
